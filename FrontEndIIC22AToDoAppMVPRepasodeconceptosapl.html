Ya vimos cómo realizar peticiones al servidor y crear un CRUD con los diferentes métodos HTTP a partir de una API de tipo REST.

También estructuramos nuestro proyecto basándonos en las buenas prácticas, teniendo en cuenta los principios más utilizados en el diseño del software:

  • KISS ("Keet it simple, stupid!"): evita el código complejo.
  • DRY ("Don't repeat yourself"): no dupliques código innecesario.
  • SOLID: representa 6 principios que facilitan la manutención de un código escalable y orientado a objetos.

Por último, y muy importante, nos encargamos de asegurar nuestra app gracias a las siguientes prácticas:

  • Autorización: verifica la identidad del usuario.
  • Autenticación: valida si el usuario tiene permiso para acceder a un recurso de la API.
  • JSON Web Tokens (JWT): es un token o clave que permite el intercambio seguro de datos, especialmente utilizados en los procesos de autenticación.
